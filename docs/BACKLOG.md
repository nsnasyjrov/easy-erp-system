
Problems:

# 1. Смена email содержит реальный дефект очереди

`UserEmailChangeConveyNotification` выполняется через очередь и читает актуальный объект `User`.

Если пользователь подтвердит новый email раньше обработки очереди:

- предупреждение может уйти уже на новый адрес вместо старого;
- `pending_email` внутри письма окажется `null` либо новым значением.

Нужно заранее сохранить `$oldEmail` и `$pendingEmail` и отправлять через `Notification::route('mail', $oldEmail)`.

Дополнительно текущий `pending_email`:

- остаётся в БД после истечения 60-минутной ссылки;
- из-за `unique` может бессрочно резервировать адрес;
- повтор того же значения отправляет ещё одну ссылку;
- замена значения инвалидирует старую ссылку — это как раз разумное поведение;
- в `ChangeEmailUserRequest` остался мёртвый `withValidator()` для уже удалённого `current_email`.
